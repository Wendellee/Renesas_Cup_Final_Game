07 · COMMUNICATION & CONTROL

通信与控制：数据分流，命令统一收口

分别处理控制、图像、跨核消息和检测结果，再由唯一执行路径驱动车辆。

遥控端实时图像与控制界面
01遥控指令
8 B · 2 Mbps · CH 76

硬件 ACK，方向释放立即转换为停车命令。

02无线图传
32 B 分片 · CH 100

NO_ACK 冗余，接收端重组并执行 CRC32 校验。

03双核通信
SDRAM + 32 位 IPC

JPEG 走共享内存，导航意图走短消息。

04检测图上传
DA16200 · TCP

M33 独占 Wi-Fi 状态机并上传检测 JPEG。

遥控 / 导航→最新命令邮箱→Vehicle Thread→GPT / 履带 / 风机500 ms 无导航更新即停车

08 · KEY DESIGN SUMMARY

关键设计总结：实时性、可靠性与可维护性

在硬件、软件和算法展开之后，归纳支撑系统稳定协作的四项设计。

01
DUAL-CORE PARTITION

视觉与控制分区

M85 处理高吞吐视觉任务，M33 独占运动控制，降低视觉阻塞对执行路径的影响。

02
DATA OWNERSHIP

图像所有权可追踪

共享 JPEG 使用双槽与完成通知，在消费完成前不允许覆盖对应缓冲区。

03
LATEST COMMAND

命令统一收口

手动和自动控制都写入单槽“最新命令”邮箱，再由 Vehicle Thread 统一执行。

04
FAIL-SAFE

控制链路超时保护

导航意图超过 500 ms 不更新时停止车轮，避免旧命令持续驱动车辆。

所有控制源→最新命令邮箱→Vehicle Thread→GPT / 履带 / 风机
