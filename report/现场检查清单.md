# 线下答辩现场检查清单

## 前一天

- [ ] 使用答辩电脑完整离线运行 `start-report.cmd`。
- [ ] 断开互联网后确认所有图片、3D 模型、翻页和全屏仍可用。
- [ ] 分别在 1920×1080 和现场投影分辨率检查文字边界。
- [ ] 完整排练两遍，目标时长 14:00–14:30。
- [ ] 关闭系统更新、通知、即时通信弹窗和屏幕休眠。
- [ ] 浏览器缩放保持 100%，收藏本地地址 `http://127.0.0.1:8124/`。
- [ ] 复制整个 `report` 目录到 U 盘作为备份。

## 设备

- [ ] 答辩电脑、电源适配器、HDMI/Type-C 转接头。
- [ ] RA8P1 Vehicle 车端、RemoteCtrl 遥控端及各自供电。
- [ ] 两颗 nRF24 天线安装牢固且不过度贴近。
- [ ] DA16200 与上位接收端仅在需要展示上传时接入。
- [ ] 光伏板或等效测试表面、车辆安全承托、绝缘垫。
- [ ] 备用线材、稳压电源、万用表、螺丝刀和胶带。

## 上台前 15 分钟

- [ ] 启动网页服务器并打开答辩页面。
- [ ] 点击全屏，计时器归零，停在封面。
- [ ] 车端和遥控端分别冷启动一次，检查 RTT 启动日志。
- [ ] 遥控端显示 `[LINK] command_tx_ch=76 video_rx_ch=100`。
- [ ] 车辆有承托时验证前进、释放停车和风机启动。
- [ ] 验证至少一帧图像出现 START、CRC PASS、JPEG PASS 和 FRAME。
- [ ] 近距离联调时避免两根天线紧贴。

## 演示安全

- [ ] 当前 MPU6050 已关闭，不进行无承托垂直板面运行。
- [ ] 90% 车轮和 80% 风机是联调值，正式动作前确认负载与温升。
- [ ] 始终有人在车辆下方提供机械承托。
- [ ] 当前 emergency stop 会同时切断运动和吸附；垂直状态下不能把它当作“停车并保持吸附”。
- [ ] 异常时先人工承托，再停止车轮和风机，最后断电。

## 演示顺序

- [ ] 双端启动。
- [ ] 图像回传。
- [ ] 手动方向与释放停车。
- [ ] 风机、速度和模式切换。
- [ ] 自动导航意图。
- [ ] 500 ms 导航失联停车。

## 失败回退

- [ ] 图传失败：停在网页第 8 页“通信与控制”，使用遥控端实机截图说明重组、CRC32 和解码链路。
- [ ] 无线干扰：展示双信道参数，说明控制 ACK 与视频 NO_ACK 冗余策略。
- [ ] 车辆动作异常：保持断电和承托，使用第 6、9、10 页说明双核分区、控制所有权和已验证指标。
- [ ] 3D 模型失败：刷新本地页面；若仍失败，不影响图片、架构和演示步骤。
- [ ] 本地端口占用：在 `report/web` 运行 `py -m http.server 8130 --bind 127.0.0.1`。
